# Agent Note: Context V2

Status: implemented

## Problem

Fosil recorded the exact model request and had durable automatic compaction, but request context had no source-level budget account, oversized retained tool results could dominate both execution and summarization requests, compaction identified replaced history primarily by run and request identities, and repository instructions depended on the model remembering to discover them. Trace could display raw request fields but could not explain which context sources consumed the budget or which values were transformed before dispatch.

Long-term memory and cross-session recall are separate product decisions. Treating compaction prose or repository instructions as memory would mix lifetimes, trust levels, and deletion semantics without an approved contract.

## Decision

The immutable session event stream remains authoritative, while each new execution and compaction request records the request-local Context Composition defined by the [agent-loop reference](../../../../docs/agent-loop.md#request-assembly). Contributions identify system instructions, workspace instructions, checkpoints, recent history, tool schemas, and tool-result transformations with local estimates, disposition, counts, and non-content-bearing provenance. The exact saved request and provider-reported terminal usage remain separate evidence.

Request projection deterministically replaces a settled tool result above 8,192 Unicode code points with a 4,096-point head and 1,024-point tail preview carrying the original size and SHA-256 identity. The same transformation applies before compaction. Canonical tool events remain unchanged, successful checkpoints record transformation evidence and selected source event sequences, and deterministic facts retain bounded tool-result substance. The [context compaction reference](../../../../docs/context-compaction.md) owns the current checkpoint and recovery contract.

Before each execution request, the server safely reads the selected workspace root's `AGENTS.md`. It accepts a stable regular file with one hard link, does not follow a final symlink, rejects a source above 1 MiB, retains at most 64 KiB, and inserts a sourced user-role context item before conversation history. Absence or rejection adds no fabricated instructions. Every step re-reads the source, while the exact admitted snapshot remains in the request event.

Trace presents Context Composition before the exact saved settings, system instructions, messages, and tool schemas. Earlier events keep their existing request detail and receive an explicit compatibility notice because all new event fields are optional.

The existing DeepSeek context thresholds remain unchanged. Context V2 does not add memory, embeddings, cross-session references, automatic permanent fact extraction, or history deletion.

## Alternatives considered

Storing workspace instructions in a second mutable session table would add synchronization and migration work while the exact request event already provides durable evidence. Appending workspace-instruction lifecycle events would require context-maintenance reducer and recovery transitions before that lifecycle is needed. Re-reading one bounded root file at request assembly keeps the source current and the dispatched snapshot inspectable.

Pruning canonical tool results would reduce retained payload but weaken Chat, Trace, recovery, and audit evidence. Projection-only pruning bounds model input while preserving the source record. Importing DeepSeek Harness's complete surface-replacement subsystem would replace already verified checkpoint and recovery contracts; exact source event sequences close the audit gap without that expansion.

Implementing long-term memory together with Context V2 remains rejected because memory needs independent scope, trust, mutation, contradiction, retrieval, and deletion decisions.

## Consequences

Every newly dispatched request can explain its source composition and transformations without replacing the exact request, and Trace exposes both views. Oversized tool output no longer places an unbounded settled result in later execution or compaction requests, while canonical evidence remains available for inspection and explicit rereading.

Projection-only pruning means a later model cannot recover an omitted middle section without reading the underlying source or rerunning a safe query. Root-only `AGENTS.md` loading does not discover nested instructions, user-global files, alternative filenames, skills, directory contents, or external changes through a watcher. Reading the file before every request adds bounded filesystem work and can observe edits between steps; the request event identifies the admitted version but not its author.

Local token estimates remain conservative approximations and must not be presented as provider billing or exact tokenizer output. Manual compaction controls and additional automatic compaction retries remain outside this decision.
